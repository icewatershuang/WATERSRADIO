# WATERS RADIO · HTTPS 流代理部署指南（多路热备版）

> 结论先行：**公共免费代理已经全线失效，唯一可靠的办法是自己部署 Worker。**
> 好消息是**完全免费、约 3 分钟**，而且可以部署 2~3 份做到「一路挂了另一路顶上」。

---

## 一、先看这个：一半的台已经能自动播了

播放器内置 **「http → https 自动升级」**：遇到 `http://` 的源，先自动换成 `https://` 直试。
源站本身支持 https 的，**根本不用代理就能播**。

2026-10 实测（272 条 http 流）：

| 情况 | 数量 | 能否播放 |
|---|---|---|
| https 直取成功（带 CORS `*`） | 约 1/3 | ✅ 直接播，无需代理 |
| https 通但没有 CORS 头 | 约 1/3 | ❌ 仍需代理 |
| 只有 http，不支持 https（多为裸 IP） | 约 1/3 | ❌ 仍需代理 |

也就是说 **约 2/3 的 http 电台仍需要一个代理**才能播。

## 二、为什么公共代理靠不住（实测数据）

我们逐一测了 30 多个「免费公共 CORS 代理」，拿 CNR / 蜻蜓的真实音频流去中转，
结果**全军覆没**：

```
✗ corsproxy.io      403
✗ codetabs          503 (error code: 1200)
✗ allorigins        500 / 超时
✗ thingproxy        Failed to fetch
✗ cors.eu.org       Failed to fetch
✗ proxy.cors.sh     Failed to fetch
✗ ...（其余 20 余个同样失败）
```

原因有三，都是结构性的，换域名救不了：

1. **免费代理普遍限流 / 已停运**，媒体流（尤其 m3u8 分片）直接被拒；
2. 它们大多跑在数据中心 IP 上，**国内电台 CDN 会直接封杀机房 IP**；
3. 音频流是长连接 + Range 请求，免费代理基本不支持。

所以播放器里保留公共代理只是**聊备一格**（成本为零），真正的主力是自建 Worker。

## 三、部署自己的 Worker（免费，约 3 分钟）

### 1. 注册 Cloudflare

打开 <https://dash.cloudflare.com/sign-up> 注册（免费，不用绑卡）。

### 2. 创建 Worker

1. 左侧菜单 **「Workers & Pages」**（计算 / Workers）
2. **「Create」** → **「Create Worker」**
3. 名字随便起，如 `waters-radio-proxy` → **「Deploy」**

### 3. 粘贴代理代码

1. 点 **「Edit code」**
2. 把编辑器内容**全部删掉**
3. 打开本项目 `worker/proxy.js`，**全选复制**，粘贴进去
4. 右上角 **「Deploy」**

### 4. 记下地址

部署成功后顶部会显示，形如：

```
https://waters-radio-proxy.你的用户名.workers.dev
```

## 四、把地址填进播放器（支持多路热备）

`index.html` 里有这样一个数组（约在 1310 行附近）：

```js
const PROXY_URLS = [
  // 'https://waters-radio.你的用户名.workers.dev',      // 主通道（账号 A）
  // 'https://waters-radio-b.你的用户名.workers.dev',    // 备用通道（账号 B）
  // 'https://waters-radio-c.你的用户名.workers.dev'     // 备用通道（账号 C）
];
```

### 只部署 1 份

把第一行的 `//` 去掉，换成自己的地址：

```js
const PROXY_URLS = [
  'https://waters-radio-proxy.你的用户名.workers.dev',
];
```

### 想要真正的「多路热备」（推荐）

同一份 `proxy.js` 代码，**换 2~3 个 Cloudflare 账号分别部署一遍**
（免费额度各自独立，互不影响），把地址依次填进去：

```js
const PROXY_URLS = [
  'https://waters-radio-a.账号A.workers.dev',   // 主通道
  'https://waters-radio-b.账号B.workers.dev',   // 备用 1
  'https://waters-radio-c.账号C.workers.dev',   // 备用 2
];
```

这样任意一路挂掉（或某区域被墙/限流），健康分机制会**自动切到下一路**，收音机不中断。

## 五、热备是怎么工作的

- **健康分**：每路代理 0~100 分。自建通道初始 100，公共代理初始 45。
- **探活**：每次打开页面，会先给每一路做一次小探测，把真的能通的那路顶上来。
- **自动切换**：
  - 请求成功 → 该路 +15 分；
  - 请求失败 → 该路 −35 分，立刻换下一路重试；
  - 播放中途挂掉 → 不换台，先换代理重连（`onSourceFailed` 里的故障转移）。
- **衰减恢复**：每 5 分钟给所有路 +5 分，避免某路被永久拉黑后无法恢复。
- **兜底**：所有路都失败时，退回直连原地址（至少不崩）。

界面上会显示状态：
- 绿色 `https 直连` —— 该台支持 https，无需代理
- 绿色 `中转·N路热备` —— 走自建 Worker，N 路待命
- 橙色 `公共代理·N路` —— 没配自建通道，只剩不靠谱的公共代理（提醒你去部署）

## 六、常见问题

**Q：代理要钱吗？**
A：不要。Cloudflare Workers 免费额度每天 10 万次请求，个人听电台远远用不完。
多账号部署也是各自免费。

**Q：会不会泄露隐私？**
A：只做转发，不记录、不存日志；且已禁掉内网地址，不能被当开放代理滥用。

**Q：换电脑 / 换浏览器要重配吗？**
A：不用。地址写在网页里，换设备打开还是走同一套通道。

**Q：APK 离线版也要代理吗？**
A：不用。APK 不是 https 环境，不受「混合内容拦截」限制，http 台可以直接播。

**Q：部署了但还是有些台播不了？**
A：可能是该台源站本身已失效（不是代理问题）。播放器内置了多源校验，
会自动标记失效台并尝试备用源。
