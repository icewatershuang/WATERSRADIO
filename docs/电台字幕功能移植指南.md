# 本地同步字幕方案（完整移植文档 · 给 AI / 开发者）

> 目标：把 WATERS RADIO 9 的「电台自动字幕」整条能力移植到**任意一个网页 / Android WebView 应用**，
> 移植后功能完整可用：英文电台自动出逐词字幕、歌曲自动出逐词歌词、中文电台自动关字幕。
> 本文档写给 AI 或开发者，**按顺序执行即可**。所有资源均免费获得，**不需要任何付费 API Key**。
>
> 本文档同时回答两个常被追问的问题：
> **① 本地字幕识别到底是什么方案（一句话版）** → 见 §0；
> **② 为什么装进去会大 90 多 MB、怎么瘦身** → 见 §9。

---

## 0. 一分钟版本（先讲清楚本地识别方案）

> **一句话**：手机上跑一个**离线神经网络语音识别模型**，从播放器正在播的声音里「旁路偷听」一份 16kHz 单声道音频，实时转成文字，再把文字按词逐词弹到屏幕上——**全程离线、不联网、不调任何云 API、不耗额外流量**。

展开成四个动作：

| 步骤 | 做什么 | 用什么 |
|---|---|---|
| ① 取声 | 用 Web Audio 从 `<audio>` 上接一根"旁路线"，拿到播放器正在播的 PCM 声音（不影响耳朵听到的声音） | `createMediaElementSource` + `ScriptProcessor(4096)` |
| ② 整形 | 下混成单声道 → 重采样到 **16kHz** → 转成 **Int16** → base64 | 网页 JS |
| ③ 识别 | 把 PCM 喂给手机本地的流式语音识别引擎，它边听边吐文字（**吐的是"从头到现在的累计文本"**） | **sherpa-onnx** 运行时 + 内置 int8 量化 **Zipformer 英文流式模型** |
| ④ 上屏 | 网页对累计文本做差分，得到新增的词，逐词渲染成字幕 | JS + CSS 动画 |

**关键点**：

- 引擎是 **sherpa-onnx**（下一节给下载地址），模型是**一次性打包进 APK** 的，装完就能用，**首次启动不需要下载任何东西**。
- 模型只认 **16kHz / 单声道 / Int16** 的 PCM；采样率或格式不对 = 识别出来全是乱码或干脆没输出。
- 它**吐的是累计文本**（第 1 秒 "HELLO"，第 2 秒 "HELLO WORLD"），**不是增量**。网页必须自己 diff，否则字幕会整段重复。
- 内置的是**英文模型**。英文台出字幕；中文台的正确做法是**关字幕**（由 §7 的判定器自动完成），而不是拿英文模型硬识别中文（会出一屏乱码）。

## 1. 能力边界（先说清楚能做什么、不能做什么）

| 能力 | 是否支持 | 说明 |
|---|---|---|
| 英文电台实时字幕 | ✅ | 离线、全程无需网络 |
| 中文电台实时字幕 | ❌（本方案默认关闭） | 需换中英双语模型，体积再增；本项目策略是中文台自动关字幕 |
| 歌曲逐词歌词（卡拉OK） | ✅（需联网查歌词库） | 靠 ICY 取歌名 → 查免费歌词库 → LRC 时间戳驱动 |
| 讲话节目自动字幕 | ✅ | 回落到 ASR 链路 |
| 离线可用 | ✅（ASR 链路） | 歌词链路需联网，取不到就自动回落 ASR |
| 需要付费 Key | ❌ | lrclib / lyrics.ovh 均免费无 Key |

## 2. 方案总览（三条链路 + 一个判定器）

```
┌─────────────────────── 音频播放链（耳朵听到的） ───────────────────────┐
│ <audio crossorigin="anonymous"> ← HLS走hls.js/MSE(blob: 同源)          │
│                                  ← 直连流走 LocalProxyServer(127.0.0.1)│
└──────────────┬────────────────────────────────────────────────────┘
               │ createMediaElementSource(audio)  ← 全部声音的唯一取声点
               ▼
   链路A：离线ASR字幕（无网络也能用）  ← 本方案的主体
   WebAudio ScriptProcessor(4096) → 下混单声道 → 重采样16kHz
   → Int16 PCM → base64 → 原生桥 asrPcm() → sherpa-onnx 流式Zipformer
   → partial 文本（累计式）→ 网页 diff → 逐词渲染字幕

   链路B：歌词同步（需联网，听歌场景）
   原生另开独立连接带 Icy-MetaData:1 抓ICY →「歌手 - 歌名」
   → lrclib.net / lyrics.ovh 取歌词 → LRC 按行+词切分 → 卡拉OK逐词渲染
   → 检测到「讲话」（ICY无分隔符/取不到歌词/ASR偏离歌词）→ 自动切回链路A

   链路C：CORS 本地代理（保证链路A取得到声音，关键！）
   127.0.0.1 ServerSocket 流式转发远端流 + Access-Control-Allow-Origin:*
   （HTTPS 无 CORS 头的直连台，不代理则 Web Audio 取到静音 → 字幕永远不出）

   判定器：电台语言判定 classifyStationLang(name)
   英文台 → 字幕开；中文台 → 字幕关；播的内容是中文（ICY）→ 也关
```

**为什么必须三条链路一起移植**：
只移植链路A，遇到 HTTPS 无 CORS 头的电台（占英文台相当比例）字幕会**静默失效**（能出声、没字幕），而且极难排查；只移植链路B则讲话节目没有字幕。三者配合才能做到「所有英语电台都能自动出字幕」。

## 4. 链路A：本地离线 ASR 字幕（核心）

### 4.1 为什么选 sherpa-onnx（选型对比）

| 方案 | 体积 | 离线 | 流式 | 结论 |
|---|---|---|---|---|
| **sherpa-onnx（Zipformer int8）** | ~68MB 模型 | ✅ | ✅ | **选用**：纯端侧、流式低延迟、Android 支持成熟 |
| Vosk | ~50MB~1GB（依模型） | ✅ | ✅ | 可用但模型体积/精度不如 Zipformer int8，本项目 v8.0 起已替换 |
| Whisper.cpp（tiny/base） | 75MB~150MB | ✅ | ❌（非流式，需分段） | 不适合"边听边出字" |
| 云端 API（讯飞/Google） | 0 | ❌ | ✅ | 要 Key、要流量、有延迟，与"离线"目标冲突 |

### 4.2 音频规格（硬性要求，错一个就全乱）

| 项 | 要求 |
|---|---|
| 采样率 | **16 000 Hz**（播放器可能是 44.1k/48k，必须重采样） |
| 声道 | **单声道**（立体声要下混） |
| 样本格式 | **Int16（小端）** |
| 传输 | base64 字符串，经 JS Bridge 传给原生 |
| 返回 | **累计（partial）文本**，每次都是从开头到当前 |

### 4.3 网页侧：音频图（只建一次）

```js
// 唯一取声点：整个应用只 createMediaElementSource 一次！
let audioCtx, source;
function ensureAudioGraph(){
  if(source) return;
  audioCtx = new (window.AudioContext || window.webkitAudioContext)();
  source = audioCtx.createMediaElementSource(audio);   // audio.crossOrigin='anonymous' 必须在设 src 之前设置
  source.connect(audioCtx.destination);
}
```

### 4.4 网页侧：PCM 采集与投喂

```js
function asrTapStart(){
  const proc = audioCtx.createScriptProcessor(4096, 1, 1);  // 已弃用但仍全平台可用（见坑4）
  const muteGain = audioCtx.createGain(); muteGain.gain.value = 0;
  source.connect(proc); proc.connect(muteGain);             // 必须连到静音 gain，否则循环放大
  proc.onaudioprocess = e => {
    const f32 = e.inputBuffer.getChannelData(0);
    const pcm16 = f32To16kMonoInt16(f32, audioCtx.sampleRate);  // 下混 + 重采样16k + Int16
    if(hasVoice(pcm16)) {                                       // 简单能量门限省电
      window.WatersNative.asrPcm(base64(pcm16.buffer));         // → 原生 → sherpa-onnx
    }
  };
}
```

### 4.5 原生侧：AsrController 要点

- 加载 `assets/asr/` 下 3 个 onnx + `tokens.txt` → 建 `OnlineStream`；
- `feedPcm(byte[] pcm16k)` 持续喂；识别结果经 `evaluateJavascript("window.__asrText('…')")` 回推网页；
- **PCM 队列上限 64 包（≈16s）做背压**，满了丢旧包（低端机识别慢于播放时必须丢，否则字幕越来越滞后、内存膨胀）；
- `isAvailable()`：API ≥ 21 且非低内存设备再启用；
- **partial 是累计文本**（每包都从开头到当前），网页按增量 diff 渲染。

### 4.6 字幕渲染规范（逐词登场）

- 原生推来的 partial 是**累计文本**，网页 diff 出增量，按词拆分；
- 每个词一个 `<span class="sub-word">`，CSS `animation: pop .18s` 逐词弹出；
- 按屏宽自动换行、**零滚动**；竖屏字幕区高 ~228px / 横屏 ~204px 固定约束；
- 收到新增量时给最新词加 `.pop` 动画类，历史词保持常显。

## 5. 链路B：歌词同步（听歌场景）

1. 原生**独立连接**（与音频流分开）对 stream URL 带 `Icy-MetaData:1`，解析 `meta-interval` 与 `StreamTitle='歌手 - 歌名'`，`__onIcy()` 推网页；
2. 网页解析出 `artist / title`（分隔符 `- – — － |`）→ 依次请求：
   - lrclib：`/api/search?artist=&track_name=`，取 `syncedLyrics`（带 `[mm:ss.xx]` 时间戳）
   - 兜底 lyrics.ovh：`/v1/{artist}/{title}`（纯文本，无时间戳，退化为整段显示）
3. LRC 按行切分再按空格切词 → 用 `setInterval` 按墙钟推进高亮词（卡拉OK 效果）；
4. **讲话检测切回 ASR**：ICY 无分隔符 / 歌词取不到 / ASR 识别文本与当前歌词行重叠度骤降 → `stopLyricsRender()` 回链路A。

> ICY 抓取**不走本地代理**，原生用原始远端地址独立连接，与播放链路互不干扰（见坑 8）。

## 6. 链路C：CORS 本地代理（没有它一半英文台没字幕）

**根因**：`<audio crossorigin="anonymous">` 直连「无 `Access-Control-Allow-Origin` 响应头」的远端流时，`createMediaElementSource` 拿到的 PCM 是被同源策略**污染的静音** → ASR 无输入。
HLS 走 MSE 是 `blob:` 同源不受影响；**HTTPS 直连台是重灾区（能出声、字幕永不出）**。
注意：`MIXED_CONTENT_ALWAYS_ALLOW` 只放行**播放**，**不放开同源策略**，救不了这个。

**实现要点**（`LocalProxyServer.java`，约 300 行，可直接照本项目移植）：

- `ServerSocket` 监听 `127.0.0.1:8123`；`GET /stream?u=<urlencoded 远端地址>`；
- 响应头固定带 `Access-Control-Allow-Origin: *` + `Content-Type: audio/mpeg`（不解析上游类型也行）；
- **忽略 Range**（直播流没有意义），上游带浏览器 UA / 上游 Origin/Referer，HTTPS 放宽证书校验（老设备兼容自签流）；
- 纯流式管道转发（8KB 缓冲），**客户端断开立即停上行**（省流量）；
- 网页侧 `proxify()`：APK 内对**非 HLS 直连流**统一包 `localProxyBase() + encodeURIComponent(url)`；单台代理失败（`onerror`）→ **只回退该台直连**，不影响其它台；
- 启动失败不影响播放（代理是"增强项"，不是"必需项"）。

## 7. 判定器：电台语言判定（照抄即可）

```js
function classifyStationLang(name){           // 返回 'en' | 'zh'
  if(!name) return 'en';
  const nm = String(name);
  if(/英语|英文|english/i.test(nm)) return 'en';                        // ① 强英文标识优先
  if(/之声|广播|电台|交通|新闻|经济|文艺|生活|都市|乡村|戏曲|评书|曲艺|粤语|普通话|华语|中文|央广|大湾区|民族|农业|老年|少儿|故事/.test(nm)) return 'zh';  // ② 中文强关键词
  if(/[\u3400-\u9FFF\u3040-\u30FF]/.test(nm)) return 'zh';             // ③ 含 CJK 字符
  return 'en';                                                          // ④ 纯英文名默认英文台
}
```

**两层判定配合**：

- **切台时按台名判定**：`zh` → 关字幕（识别照跑但不上屏）；`en` → 开字幕，并**清掉该台历史误记的「中文台」标记**；
- **ICY 内容级兜底**：ICY 文本含 CJK → 按内容判中文关字幕，**但台名带「英语/英文/English」强标识的台绝不关闭**（真实案例：`Cri英语资讯广播` 台名含中文但内容是英文，靠规则① 保它永远开字幕）。

## 8. 原生 ↔ 网页接口契约（移植时必须逐一实现）

| 方向 | 方法 | 说明 |
|---|---|---|
| 网页→原生 | `isApp(): boolean` | 网页判断是否在 APK 内 |
| 网页→原生 | `asrPcm(b64: String)` | 16kHz 单声道 Int16 PCM（base64）持续投喂，**链路A 入口** |
| 网页→原生 | `setAsr('1'/'0')` / `setAsrLang(lang)` | 开关 / 语言同步（**必须实现**，见坑 11） |
| 网页→原生 | `localProxyBase(): String` | 返回 `http://127.0.0.1:8123/stream?u=`（代理没起来返回空串） |
| 网页→原生 | `setSchedule(json)` / `getPendingAlarm(): String` | 定时 / 闹钟（可选移植） |
| 网页→原生 | `onNowPlaying(...)`、`standby()`、`setImmersive()` 等 | ICY 展示 / 待机 / 沉浸（可选） |
| 原生→网页 | `evaluateJavascript("window.__onIcy('…')")` | ICY 文本推给网页（触发歌词同步） |
| 原生→网页 | `evaluateJavascript("window.__asrText('…')")` | 识别 partial 文本推给网页（驱动字幕渲染） |

**原生侧核心类职责**：

| 类 | 职责 | 关键点 |
|---|---|---|
| `MainActivity` | 加载 `file:///android_asset/index.html`，注入 `WatersNative` 桥 | 前台服务保活播放 |
| `RadioPlaybackService` | 前台服务：持音频会话、MediaSession、ICY 拉取、ASR 接收 | `onCreate` 里**必须启动 LocalProxyServer**；`onDestroy` 停止 |

## 9. 体积预算与瘦身（为什么会有 90 多 MB）

### 9.1 v9.1.24 实测拆解（APK 92.2MB / 解压后 122.9MB）

| 组成 | 大小 | 占比 | 说明 |
|---|---|---|---|
| **ASR 模型** | **67.6 MB** | **55%** | 其中 `encoder.int8.onnx` 独占 66.9MB；因 `noCompress 'onnx'` 几乎压不动 |
| **原生 .so 库** | **51.6 MB** | **42%** | **打了两套 ABI**：arm64-v8a 30.4MB + armeabi-v7a 21.2MB（`libonnxruntime.so` 两者合计 35.8MB） |
| dex（Java 代码） | 2.6 MB | 2% | |
| 网页（index.html + hls.js） | 0.9 MB | ~1% | |

**结论**：真正的应用逻辑只有 **3.5MB 左右**，另外 **~89MB 全是"让离线识别跑起来"的代价**（模型 + ONNX Runtime）。

### 9.2 四条瘦身路径（按性价比排序）

| # | 做法 | 省下 | 代价 |
|---|---|---|---|
| ① | **只打 arm64-v8a**（`abiFilters 'arm64-v8a'`） | **−21MB**（APK → ~71MB） | 放弃 2017 年前的 32 位老设备（目前占比很低） |
| ② | **改 App Bundle / ABI 分包** | 用户实际下载 −21~30MB（商店按 ABI 下发） | 需要改发布方式（aab + 商店），侧载分发变麻烦 |
| ③ | **换更小的流式模型**（如 zipformer small / 非 int8 之外的小模型） | −20~40MB | 识别准确率下降，字幕错词变多 |
| ④ | **模型改成首次启动下载** | APK → ~25MB | 首次使用必须联网、要等下载；违背"装上就能离线用"的设计目标 |

> 推荐组合：**① 只打 arm64** 是最省事且几乎无感的；如果要上架商店，**② + ①** 是终局方案。

## 10. 已知坑清单（每一条都真实踩过）

1. **CORS 污染**（§6）：现象是「有声音、没字幕」——不要先去查 ASR，**先查音频源 CORS**。
2. **模型 `noCompress`**：`assets/` 里的 `.onnx` 不加 `noCompress 'onnx'` 会被压缩，运行时读不到 → 识别永远不就绪。
3. **partial 是累计文本**：不是增量！网页必须自己 diff，否则字幕整段重复。
4. **ScriptProcessor 已弃用但仍是最稳方案**：AudioWorklet 在 WebView 老内核兼容性差，v9 线实测 ScriptProcessor 在 Android 5~15 全可用。
5. **`touch-action:none`**：手势容器必须加，否则真机滑动被浏览器拦截触发 `pointercancel`，横滑切台 / 竖滑调音量全失效。
6. **只准一次 `createMediaElementSource`**：重复调用会抛错且音频图报废。
7. **PCM 背压**：低端机识别慢于播放时，队列必须限量（64 包）丢旧包，否则内存膨胀 + 字幕越来越滞后。
8. **ICY 与音频分离**：ICY 必须原生另开连接；若跟音频同连接，本地代理 / 换源后 ICY 就丢了。
9. **debug 签名每次不同**：CI 侧载分发要提醒用户先卸载旧版，否则 `INSTALL_FAILED_UPDATE_INCOMPATIBLE`。
10. **中文模型**：英文模型识别中文只会出乱码 → 中文台的正确做法是**关字幕**（§7），而不是换模型。
11. **⚠️ 删设置板块的"副作用"陷阱**：`syncSubtitleAvailability()` 看着只是「显隐语音字幕开关」，实际是**唯一把 `asrOn`/`asrLang` 同步给原生层（`setAsr`/`setAsrLang`）的入口**。本项目 v9.1.23 删设置板块时连带删掉它 → 原生 ASR 从未开启 → **字幕全灭**。
    **教训：删任何 UI 板块前，先确认它的绑定里有没有"副作用同步 / 初始化"逻辑。**
12. **⚠️ 跨 `<script>` 作用域陷阱**：主页面主体全在 `init()` 内，而某些模块（如定时器 / 闹钟）在独立 `<script>` 里 —— 那里的 `playStation` / `toast` / `setVolume` 一律 `undefined`（曾导致闹钟不切台、定时不播放、提示静默 ReferenceError）。
    **修法：在 `init()` 末尾显式挂 `window.xxx = xxx`。** 排查"看着能用但不生效"的问题时，先确认跨 script 的函数是否真的可见。

## 11. 给 AI 的分步实施计划（M0–M7，按顺序做完就能跑）

| 里程碑 | 任务 | 完成判据 |
|---|---|---|
| **M0** | 搭壳：WebView 加载本地 `index.html`，注入 `WatersNative.isApp()` | 网页能判断"在 App 内" |
| **M1** | 播放器能播 HLS 与直连流（引入 hls.js），`crossOrigin='anonymous'` | 有声音 |
| **M2** | 接 `sherpa-onnx` AAR + Gradle `noCompress 'onnx'`，模型 4 文件放 `assets/asr/` | 原生日志打印"模型加载成功" |
| **M3** | 建音频图 `ensureAudioGraph()` + PCM 采集 `asrTapStart()` + 桥 `asrPcm()` | 原生能持续收到 PCM 包 |
| **M4** | `AsrController.feedPcm` + 回推 `__asrText()` + 网页 diff 渲染 | **HLS 台出现字幕**（此时 HTTPS 直连台还没有，正常） |
| **M5** | 实现 `LocalProxyServer` + `localProxyBase()` + `proxify()` + 单台失败回退 | **HTTPS 无 CORS 头直连台也出字幕** |
| **M6** | ICY 抓取 + lrclib/lyrics.ovh + 卡拉OK 渲染 + 讲话回落 ASR | 英文台播歌出逐词歌词，讲话时自动回 ASR |
| **M7** | `classifyStationLang()` 判定器 + 中/英文台开关逻辑 + 设置项与原生同步 | 英文台恒开、中文台恒关、CRI 类台不被误关 |

**做完 M0–M5 就已经具备"本地同步字幕"的完整能力**，M6/M7 是体验增强。

## 12. 验收清单

- [ ] HLS（m3u8）台：有声音 + 字幕正常
- [ ] HTTP 直连台：有声音 + 字幕正常
- [ ] **HTTPS 无 CORS 头直连台：有声音 + 字幕正常**（链路C 生效的铁证）
- [ ] 单台代理失败：该台自动回退直连，其它台不受影响
- [ ] 英文台播歌：ICY 命中 → 逐词歌词；讲话 → 自动切回 ASR 字幕
- [ ] 台名含「英语/英文/English」但含中文（如 CRI 类）：字幕恒开
- [ ] 中文台（中文关键词 / CJK 台名）：字幕不出、无乱码
- [ ] 纯英文名台播中文内容：ICY CJK 兜底关字幕
- [ ] 锁屏 / 后台 30 分钟：字幕持续、服务不被杀
- [ ] 低端机（API 21~24）：不崩、字幕延迟 < 5s
- [ ] 断网：字幕照样出（证明离线 ASR 生效）
