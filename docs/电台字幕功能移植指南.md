# 电台字幕功能移植指南（给 AI 的完整实现说明）

> 目标：把 WATERS RADIO 9 的「电台自动字幕」整条功能移植到**任意一个网页 / Android WebView 应用**里，
> 移植后功能完整可用：英文电台自动出逐词字幕、歌曲自动出逐词歌词、中文电台自动关字幕。
> 本文档写给 AI 或开发者，按顺序执行即可。所有资源均可免费获得，**不需要任何付费 API Key**。

---

## 一、功能全景（三条链路 + 一个判定器）

```
┌─────────────────────── 音频播放链（耳朵听到的） ───────────────────────┐
│ <audio crossorigin="anonymous"> ← HLS走hls.js/MSE(blob:同源)          │
│                                  ← 直连流走 LocalProxyServer(127.0.0.1)│
└──────────────┬────────────────────────────────────────────────────┘
               │ createMediaElementSource(audio)  ← 全部声音的唯一取声点
               ▼
   链路A：离线ASR字幕（无网络也能用）
   WebAudio ScriptProcessor(4096) → 下混单声道 → 重采样16kHz
   → Int16 PCM → base64 → 原生桥 asrPcm() → sherpa-onnx 流式Zipformer
   → partial 文本（累计式）→ 网页逐词渲染字幕

   链路B：歌词同步（需联网，听歌场景）
   原生另开独立连接带 Icy-MetaData:1 抓ICY →「歌手 - 歌名」
   → lrclib.net / lyrics.ovh 取歌词 → LRC 按行+词切分 → 卡拉OK逐词渲染
   → 检测到「讲话」（ICY无分隔符/ASR偏离歌词）→ 自动切回链路A

   链路C：CORS 本地代理（保证链路A取得到声音，关键！）
   127.0.0.1 ServerSocket 流式转发远端流 + Access-Control-Allow-Origin:*
   （HTTPS 无 CORS 头的直连台，不代理则 Web Audio 取到静音 → 字幕永远不出）

   判定器：电台语言判定 classifyStationLang(name)
   英文台 → 字幕开；中文台 → 字幕关；播的内容是中文（ICY）→ 也关
```

**为什么必须三条链路一起移植**：只移植链路A，遇到 HTTPS 无 CORS 头的电台（占英文台相当比例）字幕会静默失效（能出声、没字幕）；只移植链路B则讲话节目没有字幕。三者配合才能做到「所有英语电台都能自动出字幕」。

## 三、原生侧（Android WebView 壳）移植步骤

### 3.1 Gradle 配置（缺一不可）

```groovy
android {
    aaptOptions { noCompress 'onnx' }        // ★ 模型不可压缩，否则运行时读不到
    packagingOptions {
        jniLibs { useLegacyPackaging = true }
        pickFirsts += ['lib/**/libonnxruntime.so']
    }
    // 若直接把 sherpa 的 Java 封装源码拷进工程，需压制其依赖冲突：
    // configurations.all { resolutionStrategy { force '...'; } }
}
dependencies {
    implementation 'androidx.appcompat:app:1.x'      // WebView 壳
    implementation files('libs/sherpa-onnx.aar')      // 见资源表
}
```

- 权限：`INTERNET`、`FOREGROUND_SERVICE`、`FOREGROUND_SERVICE_MEDIA_PLAYBACK`、`POST_NOTIFICATIONS`（Android 13+ 前台服务通知）。
- `network_security_config.xml`：`base-config cleartextTrafficPermitted="true"`（放行 http 电台流 + 127.0.0.1 回环）。
- WebView 设置：`javaScriptEnabled`、`mediaPlaybackRequiresUserGesture=false`、`mixedContentMode=MIXED_CONTENT_ALWAYS_ALLOW`。
  ⚠️ 注意：`ALWAYS_ALLOW` 只放行**播放**，**不放开同源策略**——所以 CORS 污染依旧存在，这正是链路C存在的原因。

### 3.2 核心类与职责（可直接照抄结构）

| 类 | 职责 | 关键点 |
|---|---|---|
| `MainActivity` | 加载 `file:///android_asset/index.html`，注入 `WatersNative` 桥 | 前台服务保活播放 |
| `RadioPlaybackService` | 前台服务：持 WebView 音频会话、MediaSession 锁屏/蓝牙控制、ICY 拉取、ASR 接收 | `onCreate` 里**必须启动 LocalProxyServer**；`onDestroy` 停止 |
| `AsrController` | 封装 sherpa-onnx：加载 3 个 onnx + tokens → `OnlineStream`；`feedPcm(byte[] pcm16k)` 持续喂；识别结果经桥回传网页 | pcmQ 队列上限 64 包（≈16s）做背压；**partial 是累计文本**（每包都从开头到当前），网页按增量diff渲染；`isAvailable()`：API≥21 且非低内存设备 |
| `LocalProxyServer` | 127.0.0.1 流式代理（详见 §五） | 端口固定（如 8123），启动失败不影响播放 |
| `AlarmScheduler/AlarmReceiver` | 闹钟/定时（可选移植） | AlarmManager RTC_WAKEUP 精确闹钟；触发项落盘，网页起来后 `getPendingAlarm()` 消费 |

### 3.3 JsBridge 接口契约（网页 ↔ 原生，移植时必须逐一实现）

| 方向 | 方法 | 说明 |
|---|---|---|
| 网页→原生 | `isApp(): boolean` | 网页判断是否在 APK 内 |
| 网页→原生 | `asrPcm(b64: String)` | 16kHz 单声道 Int16 PCM（base64）持续投喂，链路A入口 |
| 网页→原生 | `setAsr('1'/'0')` / `setAsrLang(lang)` | 开关/语言同步（可选） |
| 网页→原生 | `localProxyBase(): String` | 返回 `http://127.0.0.1:8123/stream?u=`（代理没起来返回空串） |
| 网页→原生 | `setSchedule(json)` / `getPendingAlarm(): String` | 定时/闹钟（可选移植） |
| 网页→原生 | `onNowPlaying(...)`、`standby()`、`setImmersive()` 等 | ICY 展示/待机/沉浸（可选） |
| 原生→网页 | `evaluateJavascript("window.__onIcy('…')")` | ICY 文本推给网页（触发歌词同步） |
| 原生→网页 | `evaluateJavascript("window.__asrText('…')")` | 识别 partial 文本推给网页（驱动字幕渲染） |

## 四、网页侧移植步骤

### 4.1 音频图（链路A的心脏）

```js
// 唯一取声点：整个应用只 createMediaElementSource 一次！
let audioCtx, source;
function ensureAudioGraph(){
  if(source) return;
  audioCtx = new (window.AudioContext||window.webkitAudioContext)();
  source = audioCtx.createMediaElementSource(audio);   // audio.crossOrigin='anonymous' 必须在设 src 前设
  source.connect(audioCtx.destination);
}
```

### 4.2 PCM 采集与投喂

```js
function asrTapStart(){
  const proc = audioCtx.createScriptProcessor(4096, 1, 1);  // 已弃用但仍全平台可用
  source.connect(proc); proc.connect(muteGain);             // 必须连到静音 gain，否则循环放大
  proc.onaudioprocess = e => {
    const f32 = e.inputBuffer.getChannelData(0);
    const pcm16 = f32To16kMonoInt16(f32, audioCtx.sampleRate);  // 下混+重采样16k+Int16
    if(hasVoice(pcm16)) ws( /* base64(pcm16.buffer) → WatersNative.asrPcm */ );
  };
}
```

要点：**重采样到 16kHz 单声道 Int16**（sherpa 要求）；可加简单能量门限省电（静音包不投喂）。

### 4.3 字幕渲染规范（逐词登场）

- 原生推来的 partial 是**累计文本**，网页 diff 出增量，按词拆分；
- 每个词一个 `<span class="sub-word">`，CSS `animation: pop .18s` 逐词弹出；
- 按屏宽自动换行、**零滚动**；竖屏字幕区高 ~228px / 横屏 ~204px 固定约束；
- 收到新增量时给最新词加 `.pop` 动画类，历史词保持常显。

### 4.4 歌词同步（链路B）

1. 原生独立连接（**与音频流分开**）对 stream URL 带 `Icy-MetaData:1`，解析 meta-interval 与 `StreamTitle='歌手 - 歌名'`，`__onIcy()` 推网页；
2. 网页解析出「artist / title」（分隔符 `- – — － |`）→ 依次请求 lrclib（`/api/search?artist=&track_name=`，取 `syncedLyrics`）→ lyrics.ovh 兜底；
3. LRC `[mm:ss.xx]` 按行切分再按空格切词 → 用 `setInterval` 按墙钟推进高亮词（卡拉OK）；
4. **讲话检测切回 ASR**：ICY 无分隔符 / 歌词取不到 / ASR 识别文本与当前歌词行重叠度骤降 → `stopLyricsRender()` 回链路A。

### 4.5 电台语言判定（移植时照抄规则）

```js
function classifyStationLang(name){           // 返回 'en' | 'zh'
  if(!name) return 'en';
  const nm = String(name);
  if(/英语|英文|english/i.test(nm)) return 'en';                        // ① 强英文标识优先
  if(/之声|广播|电台|交通|新闻|经济|文艺|生活|都市|乡村|戏曲|评书|曲艺|粤语|普通话|华语|中文|央广|大湾区|民族|农业|老年|少儿|故事/.test(nm)) return 'zh';  // ② 中文强关键词
  if(/[\u3400-\u9FFF\u3040-\u30FF]/.test(nm)) return 'zh';             // ③ 含CJK字符
  return 'en';                                                          // ④ 纯英文名默认英文台
}
```

两层判定配合：
- **切台时按台名判定**：zh → 关字幕（识别照跑但不上屏）；en → 开字幕，并清掉该台历史误记的「中文台」标记；
- **ICY 内容级兜底**：ICY 文本含 CJK → 按内容判中文关字幕，**但台名带「英语/英文/English」强标识的台绝不豁免关闭**（案例：`Cri英语资讯广播` 台名含中文但内容是英文，台名①规则已保它永远开字幕）。

## 五、链路C：CORS 本地代理（没有它一半英文台没字幕）

**根因**：`<audio crossorigin="anonymous">` 直连「无 `Access-Control-Allow-Origin` 响应头」的远端流时，`createMediaElementSource` 拿到的 PCM 是被同源策略**污染的静音** → ASR 无输入。HLS 走 MSE 是 `blob:` 同源不受影响；**HTTPS 直连台是重灾区**（能出声、字幕永不出）。

**实现要点**（`LocalProxyServer.java`，约 300 行，可直接照本项目移植）：
- `ServerSocket` 监听 `127.0.0.1:8123`；`GET /stream?u=<urlencoded 远端地址>`；
- 响应头固定带 `Access-Control-Allow-Origin: *` + `Content-Type: audio/mpeg`（不解析上游类型也行）；
- **忽略 Range**（直播流没有意义），上游带浏览器 UA / 上游 Origin/Referer、HTTPS 放宽证书校验（老设备兼容自签流）；
- 纯流式管道转发（8KB 缓冲），**客户端断开立即停上行**（省流量）；
- 网页侧 `proxify()`：APK 内对**非 HLS 直连流**统一包 `localProxyBase()+encodeURIComponent(url)`；单台代理失败（onerror）→ 只回退该台直连，不影响其它台；
- ICY 抓取**不走代理**（原生用原始远端地址独立连接），互不干扰。

## 六、已知坑清单（每一条都真实踩过）

1. **CORS 污染**：见 §五。现象是「有声音、没字幕」——不要去查 ASR，先查音频源 CORS。
2. **模型 noCompress**：`assets/` 里的 `.onnx` 不加 `noCompress` 会被压缩，sherpa 运行时读不到 → 识别永远不就绪。
3. **partial 是累计文本**：不是增量！网页必须自己 diff，否则字幕整段重复。
4. **ScriptProcessor 已弃用但仍是最稳方案**：AudioWorklet 在 WebView 老内核兼容性差，v9 线实测 ScriptProcessor 在 Android 5~15 全可用。
5. **`touch-action:none`**：主页手势容器必须加，否则真机滑动被浏览器拦截触发 pointercancel，横滑切台/调音量全失效。
6. **双线程取声**：整个 App 只允许一次 `createMediaElementSource`，重复调用会抛错且音频图报废。
7. **pcm 背压**：识别慢于播放时（低端机），PCM 队列必须限量（如 64 包）丢旧包，否则内存膨胀且字幕越来越滞后。
8. **ICY 与音频分离**：ICY 必须原生另开连接；若跟音频同连接，本地代理/换源后 ICY 就丢了。
9. **debug 签名每次不同**：CI 侧载分发要提醒用户先卸载旧版，否则 `INSTALL_FAILED_UPDATE_INCOMPATIBLE`。
10. **中文模型**：内置英文模型识别中文只会出乱码 → 中文台的正确做法是关字幕（判定器 §4.5），而不是换模型。

## 七、移植验收清单

- [ ] HLS（m3u8）台：有声音 + 字幕正常
- [ ] HTTP 直连台：有声音 + 字幕正常
- [ ] **HTTPS 无 CORS 头直连台：有声音 + 字幕正常**（链路C生效的铁证）
- [ ] 单台代理失败：该台自动回退直连，其它台不受影响
- [ ] 英文台播歌：ICY 命中 → 逐词歌词；讲话 → 自动切回 ASR 字幕
- [ ] 台名含「英语/英文/English」但含中文（如 CRI 类）：字幕恒开
- [ ] 中文台（中文关键词/CJK 台名）：字幕不出、无乱码
- [ ] 纯英文名台播中文内容：ICY CJK 兜底关字幕
- [ ] 锁屏/后台 30 分钟：字幕持续、服务不被杀
- [ ] 低端机（API 21~24）：不崩、字幕延迟 < 5s
